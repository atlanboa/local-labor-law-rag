# 국가법령정보 Open API 가이드

`lawbot`이 쓰는 API의 호출 방법과 실제 응답에서 확인한 동작을 정리한다. 수집 코드는 `src/lawbot/collect.py`에 있다.

신뢰 수준 표시:

- **[응답]** 2026-11-02에 수집한 실제 응답에서 확인했다.
- **[문서]** API 가이드에만 근거한다. 실제 응답으로 확인하지 않았다.
- 문서와 응답이 다르면 응답을 따른다.

## 인증과 호출 규칙

- 인증키는 `.env`의 `LAW_API_OC`에 둔다. 호출할 때 `OC` 파라미터로 보낸다.
- **HTTPS만 쓴다.** 가이드의 예시는 대부분 `http://`이지만, 키가 쿼리 문자열로 전송되므로 쓰지 않는다. **[응답]** `https://www.law.go.kr/DRF/`는 동작한다.
- **키를 저장하거나 출력하지 않는다.** 검색 응답의 상세 링크에는 키가 들어 있으므로 `lawSearch.do` 응답은 저장하지 않는다. `httpx`의 INFO 로그와 HTTP 오류 메시지에도 URL과 키가 들어갈 수 있다.
- 응답 형식은 `type=JSON`을 쓴다.

## 호출 순서

법률 4개는 아래 3단계를 모두 거친다. 근로기준법 시행령은 3단계를 건너뛴다.

1. 현행 판 찾기: `lawSearch.do?target=eflaw&query=<법령명>&nw=3&display=100`
   - `법령명한글`이 정확히 일치하고 `현행연혁코드`가 `현행`인 항목에서 `법령일련번호`(MST)와 `시행일자`를 읽는다.
2. 본문 받기: `lawService.do?target=eflaw&MST=<MST>&efYd=<시행일자>`
   - 응답의 `기본정보/법령ID`를 읽는다.
3. 연결표 받기: `lawService.do?target=thdCmp&ID=<법령ID>&knd=1`, `knd=2`

## 본문 응답 구조 (`target=eflaw`)

**[응답]** 최상위는 `법령`이다.

```text
법령
├ 기본정보: 법령명_한글, 법령ID, 시행일자, 공포일자, 조문시행일자문자열(있을 때만)
├ 조문/조문단위[]
│  ├ 조문여부: "조문" 또는 "전문"
│  ├ 조문번호, 조문가지번호, 조문제목, 조문내용, 조문시행일자
│  └ 항
│     ├ 항번호, 항내용
│     └ 호[]
│        ├ 호번호, 호내용
│        └ 목[]: 목번호, 목내용
├ 별표/별표단위[]: 별표구분, 별표번호, 별표가지번호, 별표제목, 별표내용
└ 부칙, 제개정이유, 개정문
```

파싱할 때 주의한다. **[응답]**

- `조문여부`가 `전문`인 행은 장 제목이다. 조문이 아니다.
- `항`은 없을 수도, 리스트일 수도, 객체 하나일 수도 있다. 항 없이 호만 있는 조문은 `항번호`와 `항내용`이 없다.
- 조문 ID는 `제{조문번호}조`에 가지번호가 있으면 `의{조문가지번호}`를 붙인다. 예: `제43조의2`.
- 번호에는 앞에 0이 붙을 수 있다. 정수로 바꾸거나 0을 지운 뒤 쓴다.
- `호번호`는 `9의2.`처럼 가지번호를 포함한다.
- `별표내용`은 글자로 그린 표가 든 중첩 리스트다. `별표번호`는 `0001`처럼 네 자리이고, 근로기준법에는 `0000`이 있다.

### 법령명 표기

남녀고용평등법의 정식 표기는 `남녀고용평등과 일ㆍ가정 양립 지원에 관한 법률`이다. 가운뎃점은 **U+318D**(`ㆍ`)이고 U+00B7(`·`)이 아니다. 청크 ID와 평가 정답은 응답의 `법령명_한글`을 그대로 쓴다.

## 연결표 응답 구조 (`target=thdCmp`)

**[응답]** 3단 비교는 법률 조문에 연결된 시행령과 시행규칙 조문을 준다. `knd`에 따라 최상위 키와 구조가 다르다.

| | `knd=1` 인용 연결표 | `knd=2` 위임 연결표 |
| --- | --- | --- |
| 최상위 키 | `ThdCmpLawXService` | `LspttnThdCmpLawXService` |
| 본문 키 | `인용조문삼단비교/법률조문[]` | `위임조문삼단비교/법률조문[]` |
| 시행령 연결 | `시행령조문목록/시행령조문` | `시행령조문` |
| 시행규칙 연결 | `시행규칙조문목록/시행규칙조문` | `시행규칙조문` |
| 조문 하나의 표현 | 한 행에 연결 여러 개 | 연결마다 같은 조문의 행이 반복 |
| 기본정보의 ID | `법령ID`, `시행령ID`, `시행규칙ID` | `법령ID` |

- 시행령과 시행규칙 조문은 객체 하나일 수도, 리스트일 수도 있다.
- 조문 번호는 `조번호`가 아니라 `조제목`(`제11조(적용 범위)`)에서 읽는다. `조번호`는 장 제목 행에도 있다.

두 표는 내용이 다르므로 합쳐서 쓴다. 근로기준법의 시행령 연결은 둘 다 48개, `knd=1`에만 16개, `knd=2`에만 12개다.

- `knd=2`: 법률이 세부 내용을 하위 법령에 맡긴 관계로 보인다. 예: 제33조와 시행령 제14조, 제15조
- `knd=1`: 하위 법령이 법률 조문을 언급한 관계로 보인다. 예: 제60조와 시행령 제33조, 제7조의2
- 이 구분은 표본에서 추론했다. 가이드에 판단 기준은 없다.

## 알려진 함정

**`target=law`는 시행 전 문구를 현행처럼 준다. [응답]** 근로기준법 제13조의 현행 문구는 "근로감독관"이지만, `target=law`는 2026-12-08 시행 예정인 "노동감독관" 문구를 주고 `조문시행일자`는 `20261008`로 표시한다. 그래서 본문은 `eflaw`로 받는다.

**`조문시행일자문자열`이 시행 예정의 근거다. [응답]** 형식은 `20261208:제13조,제101조,...` 뒤에 구분자 없이 `20270101:제44조의4,...`가 이어진다. `제110조제1호`처럼 호 단위 항목도 있다. `manifest.json`의 `article_effective_dates`에 법령별로 남는다. 다음 시행일이 지나면 다시 수집한다.

**시행령은 `thdCmp`로 조회하지 않는다. [응답]** 필요한 연결은 법률의 연결표에 있다.

- 시행령 `knd=1`은 `법령ID`에 상위 법률 값을 주고, 연결 없는 조문 목록만 준다.
- 시행령 `knd=2`는 기준 법령이 `공휴일에 관한 법률`이다.

**연결표의 시점은 본문과 다를 수 있다. [응답]** `thdCmp`에는 시행일을 지정할 수 없다. 근로자퇴직급여 보장법 `knd=2`는 시행일자가 `20260701`이고 본문은 `20260918`이다. 본문에 없는 조문으로 가는 연결은 버리고 개수를 기록한다.

**"별표 1"은 법령마다 따로 있다. [응답]** 시행령 별표 1과 시행규칙 별표 1은 다르다. 항상 법령명과 함께 다룬다.

**연결표에는 법 전체에 적용되는 규칙이 안 나온다. [응답]** 제60조는 5인 미만 적용 범위를 정한 제11조와 연결되지 않는다. 시행령 제7조에서 별표 1로 가는 연결도 조문 글에서 읽어야 한다.

**`target=law`의 `호번호` 표기는 `eflaw`와 다르다. [응답]** 같은 호를 `law`는 `2.`와 `호가지번호` `2`로 나눠 주고 `eflaw`는 `2의2.`로 준다.

## 아직 확인하지 않은 것

- **`lsDelegated`:** **[문서]** `위임구분`(시행령, 시행규칙, 인용법령, 위임행정규칙 등), `위임법령조문번호`, `조항호목`, `링크텍스트`를 준다. 연결 종류를 추론 없이 알 수 있어 `thdCmp`보다 나을 수 있다. 청킹 때 근로기준법으로 호출해 비교한다.
- **판례 `prec`:** **[문서]** 본문 조회에 `판시사항`, `판결요지`, `참조조문`, `참조판례`, `판례내용`이 있다. `참조조문`의 형식은 문서에 없다. `lawSearch.do`의 `JO`로 참조 법령을 지정할 수 있다.
- **`thdCmp`의 "데이터 없음" 응답:** 형태를 모른다. 코드는 요청과 응답의 `법령ID`를 비교해 막는다.
